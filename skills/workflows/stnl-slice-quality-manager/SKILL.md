# stnl-slice-quality-manager

## Purpose

Run one explicitly selected VALIDATE_SLICE operation on its exact current EC-1 handoff. Read the requirements, approved Plan and Task, referenced code/tests and the evidence needed for that operation. Preserve requirements, normative preparation, other deliveries and completed proof. Preparation review and implementation checks do not confer formal PASS.

## Inputs

SPEC_PATH, the explicitly selected operation and canonical slice are required. Use the exact activation returned by current inspection for begin; preserve the returned handle for all later commands.

## Minimum Reads

Current requirements, the approved selected Plan/Task, current evidence and blockers, declared product/tests/inputs, and the complete selected runner contract. Read sibling/completed proof only when the current admission requires it.

## Authority

Use `runtime/execution-current-operation.mjs inspect --spec-path SPEC_PATH` and its exact legal handoff. Admission, dispatch, literal capture, candidate composition, publication, readback and own cleanup belong to that controller. Never write operational records, counters, final results or activation directly. Preserve the returned handle and all uncertain effects. No interpreter, repair, migration or persistence adapter for earlier workflow formats is supported. Managed execution and physical REPLAN publication are unavailable; report the concrete capability block before dispatch.

Requirements and approved boundaries govern semantic scope. Authorized Areas permit effects; Expected Files are predictions. Existing Inputs are read/proof dependencies and confer no write permission. Authentication, persistence and public contract responsibilities require explicit semantic authority in addition to path containment. A mandatory checklist proves implementation progress only. Formal validation alone owns finding disposition and PASS.

Delegate each admitted check/formal to one fresh independent context. Load the complete selected runner contract before scope reads, retain its explicit path/hash, and use the official returned identity and full first finalResponse. Do not suggest the verdict, replace rejected bytes, use session directories, or turn discovery into verification evidence. The reviewed recipe runs only through the returned helper. Read the mandatory [runner invocation guide](references/runner-invocation.md) from this installed skill before selecting or spawning. The origin-bound receipt is mandatory; capture consumes the saved observation without replay.

Only the executor changes product code/tests for its approved implementation or active findings after admission. The quality manager does not implement corrections or create test coverage. A failed verification command remains evidence and cannot be hidden by a later success. Missing sufficient proof blocks PASS. Permission/sandbox denial requires preserving its full diagnostic and stopping the denied action, even when a later shell exit is zero; never retry through another path, tool, temporary setting or permission mode.

A failed marked verification command remains evidence even when a later corrected check passes. Neither the semantic command summary nor a later exit zero can erase that failure or authorize PASS in the same invocation. A demonstrated defect of the implementation remains NEEDS_FIX. Only a demonstrated defect of executor-prepared tests already required by current authority, on authorized paths in this slice and correctable within existing scope and rights, also requires NEEDS_FIX with a specific coverage finding. This includes a defective test, fixture or assertion or an objectively omitted required variant; it does not require a functional implementation bug. Identify the criterion/variant, violated contract, direct defect/omission evidence, authorized path and expected correction. Missing evidence alone does not establish a correctable test-delivery defect. The runner judges this semantically and remains read-only; only the executor corrects through APPLY_FINDINGS followed by VALIDATE_SLICE within existing budgets, with no extra call in this validation or REPLAN for a punctual omission. Invalid ad hoc checks outside this exception, access, transport, environment, insufficient authority and missing evidence without an identified correctable defect remain BLOCKED with the complete observed history. Use existing prepared checks and inspect their fixtures and assertions; the independent runner cannot create scripts or tests to fill missing coverage. Never PASS from an old suite or before sufficient evidence. A permitted destination does not authorize implicit shell temporary files. After a sandbox or permission denial, stop, retain the full diagnostic even after a final exit zero, and do not retry via another path, tool, temp setting or permission mode. A subsequent attempt requires the existing official handoff; this rule adds no retries or recovery budget.

Before claiming coverage is absent, compare the current requirement/variant, input actually persisted or supplied to the check, expected assertion, and relevant producer path. Inspect that producer and the fixture/assertion, including transformations and calls; cite paths and observed values or excerpts rather than inferring absence from fixture syntax or a test name. Distinguish required coverage from optional improvements. Every finding must demonstrate a violated current requirement or required variant on an authorized path in this slice. A preference for a stronger assertion or an unrequired literal output string is not a coverage defect. This is semantic judgment, not a deterministic guarantee from the finding's wording. Formal `commands` must be nonempty and report actually executed verification commands and exits, even for NEEDS_FIX/BLOCKED; discovery and inspection never substitute for those commands. Do not fabricate evidence to satisfy the schema.

## VALIDATE_SLICE

Run only this operation when current inspection returns its exact handoff; follow the admission/capture/publication and bounded recovery procedures above.

## Allowed Effects

Use only the current producer-owned operation and its approved scope. The executor may edit authorized product/tests after admission; the quality manager owns only the formal result through the current producer. Preserve all other authority and evidence.

## Blocks

Missing or stale authority/proof, uncertain identity or effects, an active conflicting owner, unsafe paths, exhausted budgets, missing independent contract/context, denied actions or an unavailable capability block the operation. Preserve their exact diagnostics.

## Output

Read back through `inspect` after publication. Report operation/slice, observed result, exact evidence location, publication and cleanup separately, current handoff, remaining blockers and changed areas. A completed delivery does not automatically close the execution, SPEC, U3, or acceptance items. Stop without selecting another slice.
