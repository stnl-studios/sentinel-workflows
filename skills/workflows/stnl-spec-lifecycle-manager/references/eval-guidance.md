# Eval Guidance

`evals/cases.json` is the machine-consumed case catalog; `evals/eval-cases.md` is its human index. After a substantial lifecycle change, run these commands from the Sentinel Workflows repository root: `node --test scripts/test-lifecycle-contracts.mjs`; `node --test skills/workflows/stnl-spec-lifecycle-manager/runtime/test/core.test.mjs skills/workflows/stnl-spec-lifecycle-manager/runtime/test/lifecycle.test.mjs skills/workflows/stnl-spec-lifecycle-manager/runtime/test/readiness.test.mjs skills/workflows/stnl-spec-lifecycle-manager/runtime/test/closed-spec.test.mjs skills/workflows/stnl-spec-lifecycle-manager/runtime/test/publisher.test.mjs`; `node --test scripts/test-lifecycle-validator-adversarial.mjs scripts/test-lifecycle-readiness-adversarial.mjs scripts/test-lifecycle-renderer-adversarial.mjs`; `node --test scripts/test-lifecycle-distribution.mjs`; `node --test scripts/test-runtime-context-budget.mjs`; `node --test scripts/test-subagent-packages.mjs`; `bash scripts/test-validation-runner-contract.sh`; and `bash scripts/test-launcher-contract.sh`. Generated workspaces are isolated temporary fixtures.

Each case declares an operation label, generated fixture inputs, expected validity and status, allowed changes, expected IDs, expected links, and objective assertions. The contract runner performs deterministic fixture construction, structural validation, transition validation, and file-preservation checks. The embedded runtime suite separately owns safe-publication interruption simulation. Neither executes INIT, RESUME, READINESS, or CLOSE with a model end to end.

The runner verifies positive and negative parser cases, immutable IDs and tombstones, mode boundaries, read-only `LOCAL`/`GLOBAL` READINESS simulation, coverage, references, exact close authority, safe publication, and external immutability. READINESS instructions must match the result schema: LOCAL_CLEAR or FINDINGS for LOCAL, READY or FINDINGS for GLOBAL, with no extra global_readiness field or default attestation write. Dedicated suites verify readiness-attestation schema/snapshot binding at the explicit validator and publisher, target-only normal CLOSE with its owned renderer and refusal of external candidates, exact deterministic CLOSE feature bytes, rejected OS metadata, non-cooperative publisher conflict recovery, persistent-lock exclusion, crash recovery, and runtime budgets. Also run `node --test skills/workflows/stnl-spec-lifecycle-manager/runtime/test/publisher-common-recovery.test.mjs`: real INIT/SIGKILL and copied-runtime recovery, idempotent history preservation, live/foreign/uncertain/missing or altered binding refusal, retained-backup execution guard, recovery/writer exclusion and interrupted handoff retention. A crash before any durable lifecycle binding must preserve and block; never delete its common lock to make a crash test pass. The lifecycle invocation has no model runner. For `INIT`, `SPEC_PATH` designates a nonexistent directory; existing paths are blocked. Launcher validation separately verifies explicit inputs and transient context.

Fail a change that requires a delivery workflow when execution is absent, invents requirements, changes stable IDs, accepts item YAML, hides a relevant decision, mutates during READINESS, makes CLOSE require an attestation, discards existing execution without current integral COMPLETE and ownership/retirement proof, loses canonical content, weakens coverage or inverse-link validation, or mutates protected external inputs. CLOSE is documentary and does not preserve durable implementation approval after execution is discarded. Reuse applicable prior evidence and select proportional checks for a documentary alignment; the substantial-change command list does not turn a reference-only correction into an obligatory full regression run.
