# stnl-spec-lifecycle-manager

This self-contained package maintains independent documentary feature SPECs through `INIT`, `RESUME`, `READINESS`, and `CLOSE`. It does not plan or execute implementation work.

## Installation and runtime

Copy only this directory. At use time, derive `<SKILL_ROOT>` from the directory containing the loaded `SKILL.md`; neither the current process directory nor a platform-specific skill location is authoritative. The operational entrypoints are:

- `runtime/validate-spec-lifecycle.mjs`
- `runtime/create-resume-manifest.mjs` (RESUME-only manifest scaffold)
- `runtime/create-readiness-attestation.mjs`
- `runtime/publish-spec-lifecycle.mjs`
- `runtime/prepare-init-candidate.mjs` (INIT-only prevalidation owner serialization)

Invoke them directly with `node "<SKILL_ROOT>/runtime/<entrypoint>.mjs" ...`. They use native Node modules and require no package manager, build, or repository-relative resource. The mutable publisher requires the normal Git executable in a Git workspace, solely for the bounded exclusion query below. On Darwin, copying additional members of a symlink hardlink group also requires the fixed OS executable `/bin/ln`, as bounded below. All kernels and readers remain free of subprocesses. Runtime source is executed, not loaded into the model's normal context; `SKILL.md` and the selected references retain progressive disclosure.

## Documentary contracts

An active workspace owns `feature_spec.md` plus materialized categories in `shared/`. Canonical headings are the sole ID authority, metadata is an ordered Markdown list, records retire in place, and structural relationships remain bidirectionally validated. `READINESS` is read-only. Semantic `GLOBAL/READY` over current `ready` state creates an external attestation directly. When the validated state is still `draft`, an authorized status-only `RESUME` selects `--readiness-attestation auto` instead of a manifest; the publisher validates the `ready` candidate and materializes the attestation bound to that exact snapshot before promotion. `CLOSE` renders current active ready authority, validates the exact deterministic transition, and publishes without model-authored consolidation. It requires no readiness attestation; an explicitly supplied publisher attestation must be valid and fresh. The normal CLOSE command accepts only the target; the publisher renders directly into its own stage. Execution must be absent or proved current integral COMPLETE by the normal reader; unrelated external paths remain exact. The normal CLOSE result is JSON with publication `confirmed`, cleanup `complete` or `pending`, transaction identity, requirements authority, closed snapshot digest and the derived source execution disposition. Confirmation is not an implementation PASS.

## Publication and recovery

The publisher stages a complete disjoint candidate, validates its captured digest, journals every transactional phase, renames the source to a transaction-owned backup, verifies that backup, promotes the stage, revalidates the official path, and removes transaction residue only after commit. Journal schema version 2 preserves closed transaction fields for mode, target/stage/backup roles, phase, source/candidate/observed digests and transaction identity, plus its sealed filesystem context. A strict ownership sidecar in the operational materialRoot, `.<workspace-name>.lifecycle-ownership-<transaction-id>.json`, binds that transaction to the persisted device/inode identities and digests of its stage, source, backup, and promoted target. Recovery runs under the lock before new work and either completes a verified commit or restores and validates the exact captured source. Corrupt, foreign, or inconsistent metadata is preserved and rejected rather than treated as deletion authority.

On Windows, only actual rename syscall arguments are converted with Node's native namespaced-path API. Rename retries are limited to three total attempts with deterministic short backoff, and only `EPERM`, `EACCES`, or `EBUSY` is retryable. Staging remains in the proved operational materialRoot on the same volume; targetParent, materialRoot and leaseParent are distinct bound roles and cross-parent renames synchronize both parents; validation is not repeated by the retry, persisted paths and diagnostics remain portable, and other platforms retain their single native rename behavior.

The operational `materialRoot/lifecycle.lock` is strict JSON in a single-link regular file. Acquisition writes and synchronizes a private build, atomically exposes a complete claim through the native hardlink primitive, settles the claim to one canonical link, and fails safely when the filesystem cannot provide that primitive. Version 2 adds the closed `common_lease` witness to the existing owner/operation/transaction, process ID, host, state and start time. The producer derives this witness from its real common lease before allocating a transaction: canonical execution/lock paths, stable parent and lock device/inode identities, token, exact byte digest, PID and producing host. Lifecycle transitions retain that binding. Version 1 lifecycle records remain readable; they grant no common-lease recovery authority. The common lock's existing version 1 bytes remain compatible with other consumers.

Only `recoverIncompletePublication(target)` in `runtime/lib/publisher.mjs` may transfer a retained common lease. It requires an intact producer binding, the same host and owner PID, and `kill(pid, 0)` returning `ESRCH`. A live PID (including reuse), `EPERM`, unknown liveness, absent/tampered linkage or foreign host blocks. Before transfer, existing lifecycle validators inspect journal, ownership and interrupted atomic roles without settling them. The neutral common kernel receives their typed physical witnesses and rechecks token, inode, bytes, links and stable ancestry; it never interprets a lifecycle journal or accepts a takeover callback. The host witness comes from the acquired lease's lifecycle producer, never from coincident PIDs in old sibling files.

An exclusive hardlink at `<common-lock>.recovery-<old-token>` claims retirement of that exact lease. Competing recovery cannot claim it twice. Normal acquisition checks this role before and after exclusive creation, preventing effects in the handoff gap. The claimant rechecks the bound controls and dead owner before unlinking the old canonical link, exclusively creates a new common lease, and removes only its verified retirement link. It never renames over a newly acquired foreign lease. Interrupted or changed handoff roles remain diagnostic and block new work. An interruption before a durable binding exists, or after common installation but before the lifecycle lock is rebound, also remains blocked; no ownership is reconstructed from PID, age or filenames.

Recovery then acquires lifecycle ownership in the original common→lifecycle order and persists the new real lease binding before recovering the same transaction. It checks active/uncertain execution in the target and retained stage/backup, including when the target is absent, then reuses the existing verified commit/rollback and history-preservation rules. Repeated recovery returns `false` after completion. A mutable lifecycle retry uses this recovery entry before evaluating new work; recovered INIT still diagnoses `INIT destination already exists`. Normal common acquisition continues rejecting retained leases. No timeout, generic takeover, runner-terminal inference or manual lock deletion is authorized.

A successful lifecycle release atomically persists validated `released` state. Reclaim and transaction cleanup retain their inode/payload/digest checks. The protocol coordinates accidental overlap between participating sequential writers; it does not authenticate hosts with indistinguishable identities or defend against a process rewriting all controls.

Git producers require the normal `productRoot/tmp/sentinel/` root to be ignored before allocation; non-Git producers require the explicit normal exclusion context. Controls live in the derived materialRoot and the common lease remains outside it. Old sibling controls are inspected conservatively and preserved, never migrated or removed by age or filename.

## Temporary-root exclusion before publisher writes

Both `publishCandidate(mode, target, candidate, options)` and `recoverIncompletePublication(target, options)` verify filesystem roots before acquiring a common lease or writing publication controls. In a Git workspace, the trusted root is discovered from physical ancestry. The temporary root must resolve to `<PRODUCT_ROOT>/tmp/sentinel`; symlink ancestry, divergent roots, overlap and cross-filesystem placement fail closed. The publisher runs exactly `git -C <PRODUCT_ROOT> check-ignore -q -- <TEMPORARY_ROOT>/` with separate arguments, `shell: false`, a 10-second timeout and a 16-KiB limit per output stream. A missing executable, nonzero status, timeout or excessive output blocks publication; it never falls back to a caller assertion. The query does not create the namespace. Before querying, the publisher refuses inherited `GIT_DIR`, `GIT_WORK_TREE`, `GIT_COMMON_DIR`, `GIT_INDEX_FILE` and runtime configuration injection through `GIT_CONFIG_COUNT` or `GIT_CONFIG_PARAMETERS`: `-C` alone cannot prove their repository/index/configuration authority. This conservative presence check includes empty values and `GIT_CONFIG_COUNT=0`; values are never logged and the environment is never rewritten. Normal HOME/XDG and persistent Git configuration remain in use.

For a non-Git workspace, the normal API requires `options.filesystemContext = {productRoot, temporaryRoot, excludedRoots: [temporaryRoot]}` with absolute paths and an explicit exclusion declaration from the launcher. The CLI carries the same input through `--product-root <ROOT> --temporary-root <ROOT> --excluded-root <ROOT>`, supplied together and once. This is a declaration of non-Git policy, not a Git-ignore assertion or an executable callback. Git workspaces still perform the real query even when roots are explicit. Recovery and automatic reentry retain the same context.

The distribution checker permits the fixed reviewed Git call in `runtime/lib/publisher.mjs` and the exact Darwin symlink hardlink call in `runtime/lib/closed-spec.mjs`; it rejects other programs, subcommands, callbacks, unbounded options, aliases and extra calls. This is a restrictive source contract, not a general JavaScript sandbox. It adds no persistent permission or security configuration. Both capabilities use no shell and grant no subprocess capability to shared kernels, readers or other lifecycle runtimes.

The shared copy helper runs only for additional symlink names on Darwin, using exactly `/bin/ln -P -h -- <OWNED_STAGE_SOURCE> <OWNED_STAGE_DESTINATION>` with separate arguments, `shell: false`, a two-second timeout, 4-KiB output limits and ignored stdin. The binary and flags are fixed; no caller selects an executable, environment or callback. Regular hardlinks still use Node's native link primitive; isolated symlinks use its symlink primitive. The helper seals stage/source device and inode, parent directory identities, payload and link count, requires an absent destination inside the same stage/filesystem and verifies exact physical topology afterward. Failure, missing executable or timeout blocks promotion without fallback or retry. It does not dereference a dangling, absolute or directory payload. A detected replacement blocks promotion and never authorizes deleting foreign material. These path checks do not claim atomic protection against arbitrary hostile host mutations during the OS syscall; no new persistent permission is installed.

The coordinated locator places controls, stage and backup in the operational materialRoot, with a common lease outside that removable namespace. Before deleting dispensable material, CLOSE seals its source binding and exact remaining file identities, bytes, modes and topology in the existing common lease's terminal version 2. Normal version 1 remains unchanged. Terminal recovery validates the same closed target and remaining subset before taking over from a proven dead local owner; it finishes that cleanup without rendering, republishing or recreating a removed namespace. Foreign, changed, sole-source, live or ambiguous material is preserved and blocks cleanup.

CLOSE removes only sealed dispensable roles, then the empty namespace and its last common-lease name. No eternal witness or claim is required. If the final unlink succeeds but synchronizing its parent fails, the response remains publication `confirmed`, cleanup `pending`, with `FINAL_SETTLEMENT_DURABILITY_UNCONFIRMED`; it does not claim a retained lock, reconstruct authority or report complete. Once all controls are absent, a new recovery invocation returns `false` for a valid closed document without allocating or executing anything. That documentary observation cannot recover historical transaction provenance or manufacture PASS. Missing material still required by active work needs an explicit bounded revalidation decision, not an automatic workflow restart.

## JSON and transaction artifact lifecycle

| Category | Files | Lifecycle |
|---|---|---|
| External ephemeral input | RESUME transition manifest | Captured by inode and digest, consumed after safe candidate validation and before journaling, and also removed on pre-publication failure. A replacement or unknown file is preserved. |
| Persistent evidence | Readiness attestation | Lives outside the SPEC, bound to the validated snapshot, retained across a safe promotion rollback for direct retry, and consumed by successful `CLOSE`. |
| Required recovery | Transaction journal and ownership proof | Preserved while recovery is possible or required; removed only after a verified commit or rollback. Foreign, corrupt, or inconsistent evidence is never deleted. |
| Persistent lock state | Lifecycle lock | Follows the concurrency contract below. Released state remains inspectable; active or foreign state is never age-deleted. |
| Internal temporary | Build, stage, backup, quarantine, and atomic-write temporary paths | Created outside the SPEC under transaction ownership and removed only after verified terminal state. Unknown replacements are preserved. |

No temporary JSON, manifest, helper script, or scratch report belongs inside the SPEC. Runtime diagnostics identify intentionally retained recovery or readiness evidence by exact path.

Target, candidate, manifest, attestation, lock, journal, stage, and backup paths reject traversal, symlink components, aliases, namespace collisions, and unsafe containment. Snapshot digests include bytes, entry types, link counts, and relative hardlink peers. Source and candidate digests are rechecked across validation and rename boundaries; a concurrent conflict restores the official source path before reporting failure. OS packaging metadata is outside authority and is rejected from deterministic CLOSE output.
