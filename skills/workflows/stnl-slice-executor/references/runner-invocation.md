# Native runner invocation

Without an adapter or managed context, use a fresh independent native context with no inherited conversation history. Select the installed platform runner when supported (Codex `stnl_validation_runner`, Claude Code `@agent-stnl-validation-runner`). If the native API only spawns an independent generic agent, use `fork_turns:"none"` or its platform equivalent and require that agent, before any scope reads or checks, to read and follow the complete installed runner contract (Codex `~/.codex/agents/stnl_validation_runner.toml` `developer_instructions`; Claude Code `~/.claude/agents/stnl-validation-runner.md` body). Require the installed file to identify `stnl-validation-runner` and contain its canonical contract marker; a missing, malformed, or different runner contract blocks. Give it the official preflight identity and minimum operation payload, instruct it to follow the contract's no-write rule, and capture its concluded tool result through the origin-bound native procedure below. Identify this as a contract-loaded independent agent, not a selected registered runner type. Reading `developer_instructions` from a file is task-level instruction loading; it does not confer developer-level priority or the enforcement guarantee of a registered agent. If independent spawning or exact contract loading is unavailable, block; a generic agent without that contract is not the runner. Managed launches use the pathless bridge below. The human launcher supplies no helper path or benchmark sequence.

Use this skill's start-native, bind-native, verify-native and capture-native procedure. Retain the producer receipt and reviewed verification observation; a generic or registered agent's report alone grants no persistence authority. Never replay a pending or uncertain dispatch. Managed contexts use only the configured bridge and cannot be replaced by a native spawn.

For converted EC-1/S2 `VALIDATE_SLICE` and blocking-formal `APPLY_FINDINGS`, use `runtime/execution-current-operation.mjs` instead of legacy native start/capture. The launcher supplies the explicit candidate-distribution Codex TOML path and records its hash; the independent agent loads that complete file before checks. `begin` takes `--spec-path`, `--slice`, and `--expected-activation-id`; add `--operation APPLY_FINDINGS` only when `inspect` returns that handoff. APPLY admission seals the pre-edit baseline; make approved corrections after admission and retain the same handle across controller restarts. `reserve-dispatch` returns the request and origin; spawn a fresh no-history agent for each round, bind its official canonical task name, then let it call `node VERIFICATION_HELPER verify-native --origin-file ORIGIN_FILE` once using the exact `verificationHelper` path returned by EC-1 `reserve-dispatch`. Preserve the notification's complete finalResponse as UTF-8 and pass its official identity in the `--tool-result-file` envelope to `capture-native`. A captured APPLY `TESTS_FAIL` can advance to the next round on the same owner, up to 3/3; three failures require formal `VALIDATE_SLICE` through the Q13 handoff. A terminal APPLY capture may be published, but only later independent formal validation resolves findings. After capture, `resume` may direct publication of the same bytes without another spawn or recipe. If a candidate file was left by an interrupted publication, `resume` returns `normalize`; run `normalize --handle` to prove the same owner, captured bytes, and candidate base before publishing. A concluded, origin-bound formal response with invalid result schema is published as a rejected attempt with retained raw evidence. After rejection readback, `normalize --spec-path --slice --expected-activation-id` may reserve one explicit successor with a new owner; repeated rejection exhausts this EC-1 episode. For a concluded APPLY_FINDINGS schema rejection with intact official observation, publish/read back the rejected outcome before cleanup and `normalize --spec-path --slice --expected-activation-id`. That explicit successor inherits the original three-call budget and uses findings request v2: global `round`, owner-local `invocation`, no check for the rejected call. A second rejection or third consumed call exhausts recovery; a valid TESTS_PASS still requires formal VALIDATE_SLICE. Uncertain identity, transport, or HEAD proof stops the operation. If `resume` returns `cleanup`, run `cleanup --handle` for own-only completion. This profile does not enable EXECUTE, managed mode, or the legacy malformed-result successor.
