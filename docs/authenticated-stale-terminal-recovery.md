# Recover an authenticated stale terminal observation

## Bounded production behavior

A previously complete combination can become stale after a live sibling changes and receives a new independent local validation. The sibling's new PASS does not update the old terminal judgment, which still names the previous product basis.

When every local proof is current, the reader now offers `VALIDATE_SLICE` for the same still-live integral owner of the authenticated old terminal proof. Eligibility requires the exact current terminal target and an existing verified `stnl-same-operation-context-v1` invocation binding. The new operation requires explicit terminal selection, a fresh admitted producer, verification, a new literal judgment, and ordinary publication. An active owner or old terminal PASS never supplies COMPLETE.

Quiet inspection and admission leave the old evidence, approved preparation, counters, and carriers unchanged. Publication increments the formal attempt normally and retains all evidence required by existing rules. Nothing is deleted to make the next operation eligible.

## Exclusions

- A retired/completed owner still requires the existing reviewed reopening flow. This patch does not revive an owner or change the approved set.
- A changed terminal target or normative authority remains blocked for the appropriate reviewed workflow.
- Missing, malformed, or tampered evidence still fails the existing authentication and proof validators before recovery classification.
- Legacy unbound origins cannot use this new recovery path.
- A stale local proof must be independently revalidated before terminal recovery becomes eligible.

## Relation to impact and reuse

This is authenticated-stale recovery, not an assertion that a sibling change is independent. Arbitrary shell recipes have unknown dependencies, and their directory additions remain conservative invalidations. Closed deterministic content checks may support reuse of unchanged mechanical observations under their own enforced contract, but that cannot establish independence of a broader semantic formal judgment. This patch does not add a deterministic flag, ignore additions, reuse formal PASS, or bypass fresh terminal review.

The public sibling regression covers complete A/B, a changed and freshly validated A, the stale terminal handoff, refusal of omitted terminal selection, non-completion while the owner is active, and successful fresh terminal publication without modifying the sibling proof or approved snapshot. Existing terminal regressions cover tampered origins and invocation bindings, retired owners, and changed authority.
